# 分享赠堂（优化＋邀请记录）

PRD · V2.0 · 更新日期 2026-10-27

用户选择海报和文案分享，获得符合条件的分享赠堂，并查看由分享带来的新用户咨询及邀请福利。运营在后台配置素材、统计效果、处理邀请资格和福利发放。

## 一、涉及端口 · 菜单 · 功能点

1. **学生 App｜账号 → 分享赠课**：保留原入口及剩余赠课数、已获得赠课数；优化海报选择和配文，新增邀请记录、奖励明细。
2. **新用户 H5｜分享链接／海报二维码 → 咨询页**：承接未安装 App 的访问，保留邀请来源，提交咨询并查看结果。
3. **运营后台｜订单管理 → 分享赠课 → 赠课审核**：保留历史审核、自动赠课和订单查看；海报配置支持不同赠堂数量及配文。
4. **运营后台｜订单管理 → 分享赠课 → 邀请记录／邀请奖励／数据统计**：新增邀请溯源、有效性处理、福利发放和周统计；菜单名称为设计建议。
5. **关联模块｜咨询线索、订单列表、学生产品课时账户**：共享咨询进度和奖励到账结果。接口协作见[接口说明](接口说明.md)，业务路径见[业务流程](业务流程.md)。

## 二、业务规则

### 2.1 分享记录与分享赠堂

- 用户成功调起社交平台分享面板，记为一次“已调起分享”；是否在社媒实际发布，独立记录为“已确认发布／未确认发布／取消／失败”。调起成功不能用作社媒曝光或实际发布量。
- 保留每名学生每月首次成功调起分享生成一条赠课审核记录的规则，自动审核后进入“待赠课”；第 2 次及以后仅记录分享，不再产生当月分享奖励。跨平台共享该月资格。
- 调起失败、未安装平台、仅切换海报、仅保存图片或复制文案均不消耗月度资格。已经调起后取消发布，按现有调起口径不撤销已生成的资格；若改为实际发布后赠堂，须另行确定平台可验证方式及业务规则。
- 每张海报可配置分享赠堂数量 N，N 只能为 1 或 2；以当月首次符合条件记录对应海报的数量为准。后续换海报不补差、不追加当月资格。
- 历史海报缺少赠堂配置时按原 1 堂兼容；历史订单和已经生成的奖励保留原数量。编辑海报不回算旧记录。
- 分享记录保存学生、海报及文案版本、渠道、发生时间、调起结果与来源标识。月度去重以服务端学生身份和业务月份为准。
- 月和周均建议采用 Asia/Shanghai 时区；跨地区业务时区由运营确认后统一用于页面、统计、导出。

### 2.2 分享赠堂的产品与订单规则

- 学生须存在未过期已购产品，且存在同校区、同课时分钟数的赠堂产品。已购 45min 产品只匹配 45min；已购 30min、45min 可分别匹配对应时长。
- **两堂额度不足处理建议，待确认**：同一个已购产品的剩余赠课数须 ≥ N；不足时不拆分产品、不降为 1 堂，状态为“不可赠”，原因“剩余赠课数不足”。该建议影响产品筛选和订单数量，见第八章 D01。
- 符合条件的已购产品按剩余课次数从少到多排序，默认选择最少者。并列时建议按产品到期时间由近到远、再按产品编号升序；单选且切换取消原选中项。
- 赠堂产品沿用既有五种产品配置，名称为“分享贈堂-{课时分钟}”，适用校区取已购产品校区。90min 等无对等赠堂产品时不可赠。
- 订单确认默认值：订单类型“赠送”、交易类型“常规”、归属为所选已购产品所属顾问、来源“系统下单”、赠送课次 N，自动提交。
- 付款确认默认值：付款链接“后台自选”、付款类型“全款”、支付方式“线下汇款”、收款账户“赠送账户”、实际支付时间为处理时刻、备注为产品名称，金额 0。
- 创建订单、付款确认和课时入账全部成功后，状态为“已赠课”，所选已购产品已获赠课数 +N、剩余赠课数 −N。任一步失败保留“待赠课”，后台查看原因并重试；重试复用原订单和奖励，不重复赠堂。
- 无未过期产品、无对等赠堂产品、剩余赠课数不足分别显示对应不可赠原因。
- 订单列表新增支付成功的赠送订单，隐藏编辑按钮；详情购买课次数为 0、赠送课次为 N，展示学生、产品、归属、支付信息和关联奖励记录。
- 历史上传凭证的待审核记录保留人工审核能力；历史凭证、订单和快照继续可查。

### 2.3 邀请来源与关系

- 每次生成可分享内容时创建来源标识，关联邀请学生、活动、海报版本、文案版本及所选渠道。文字链接和海报二维码指向同一咨询承接页，使用同一来源标识。
- 记录用户在 App 选择的渠道；他人转发后仍保留原邀请来源，不能将所选渠道当作最终访问者实际所在平台。
- 网页打开时保留来源，咨询提交时将来源与线索绑定；来源参数不得包含明文手机号。服务端校验标识有效性和归属，不能接受前端任意填写邀请人编号。
- 有效链接访问记入访问统计；匿名访问不出现在 App 邀请明细。成功提交可识别的咨询后，出现“已提交咨询”记录。
- **归属建议，待确认**：首次有效咨询提交时锁定该提交所携带的有效来源；同一被邀请人在同一活动只归属一个邀请人，后续重复提交不覆盖。标识缺失、失效或无法核实时记为来源未知。
- 手机号应包括国家／地区代码并归一化后去重；新用户资格还需查询已有账号、历史咨询或购买记录，具体“新用户”定义见 D02。
- 邀请人本人、重复线索或不符合活动条件的记录不产生邀请奖励；邀请有效期、跨活动重复参与、跨设备来源补录见 D03。
- 客服有可靠邀请码或原分享证据时，可申请补录／纠正来源。指定权限人员处理，保存原值、新值、原因、凭据、操作人和时间；奖励已发的归属变更进入异常处理，不自动给第二个人发奖。
- 海报隐藏／删除后不再用于新分享，已有来源记录和内容快照仍可追溯。历史链接能否继续参与按活动有效期判断，不以海报是否可选判断。

### 2.4 邀请资格与奖励

- 邀请进度为“已提交咨询 → 有效邀请／未符合条件”；客服确认结果须附处理时间，未符合条件须记录原因。
- **有效邀请门槛建议，待确认**：提交可联系的咨询且客服确认有效。注册、预约、试听或购买是否纳入门槛由运营选择，不能仅因访问页面自动发奖。
- 邀请奖励单独记账，与每月分享赠堂分别展示。每月分享资格用完后仍可继续邀请；同一邀请奖励事件只能生成一条福利记录。
- 邀请奖励数量、福利类型、奖励上限、适用产品、是否占用已购产品赠课额度、与分享赠堂是否叠加及到账学生，由 D04 确定。海报的“分享赠 1／2 堂”不自动成为邀请奖励配置。
- **发放方式建议，待确认**：有效邀请审核后进入“待发放”，授权运营确认发放；状态为待发放、发放中、已发放、发放失败、不予发放。失败保留原因并可重试，处理中不可重复提交。
- 只有课时账户实际入账后，App 才显示“已到账”。邀请有效性与奖励状态分别显示，例如“有效邀请／待发放”。
- 活动配置须包含奖励条件、数量、有效期、上限、适用人群和奖励到账对象。关键业务规则未确定时可保存草稿，不可开启发奖。
- 活动规则修改时保留版本：资格确认时保存适用规则版本；已确认资格不因后续配置变化重算。按旧规则审核的跨期线索范围由 D03 确定。
- 错误确认或误发由授权人员更正并留痕。已到账福利不能直接删除记录；未使用与已使用课时的追回方案见 D05。

## 三、学生 App 与新用户 H5

### 3.1 分享赠课页

- 账号页入口和底部导航保持原行为，保留两张紧凑数据卡“剩余赠课数”“已获得赠课数”，口径继续为既有分享赠课；邀请奖励另设汇总，不混入剩余分享额度。
- 海报改为横向滚动卡片：当前项居中清晰展示，相邻项露出边缘并略微缩小，形成层次。手势滑动和点击两侧均可切换，显示位置“当前序号／总数”；不自动轮播。
- 默认选择后台排序第一张显示海报，最多展示 10 张；海报区不展示累计分享次数或右上角海报标题。海报完整等比呈现，长图允许查看大图，不能裁掉正文和二维码。
- 切换时同时更新当前图片、默认文案和本张海报分享赠堂数。已编辑文案未分享时，切换海报应先确认放弃或取消切换，避免静默丢失。
- 配文首期采用后台预设文案自动匹配，可选择备选、编辑和复制；文案建议上限 300 字，待 D06 确认。无配文时可只分享图片或自行填写。AI 自动生成属于待确认方案，不默认纳入首期。
- 分享内容包含可追踪链接，分享海报包含可识别二维码；适配平台能携带的内容。无法自动带入文字时提供复制文案及链接的操作和提示。
- 底部仍按 Facebook、Instagram、朋友圈、WhatsApp、保存排列。实际分享以各平台允许的方式接入；不保证均能直达指定帖子或动态页，具体接入见接口说明。
- 保存应保存当前选中、包含邀请二维码的分享海报；保存和复制本身不产生分享赠堂资格。返回分享页保留选择及已编辑文案。
- 无海报显示“暂无可分享海报，请稍后再试”，禁用分享；图片失败可重试或换图；平台未安装提示保存海报、复制文案后手动分享；调起失败可重试且不消耗资格。

### 3.2 我的邀请

- 分享赠课页增加“我的邀请”入口，展示已提交咨询人数、有效邀请人数和已到账邀请奖励。奖励数量按福利类型分别汇总。
- 列表展示脱敏姓名／手机号尾号、首次咨询提交时间、邀请进度、奖励进度，按首次提交时间倒序分页；相同时间按记录编号稳定排序。
- 点开详情展示对应海报及文案、渠道、咨询提交／资格确认／奖励到账时间、奖励内容、适用范围和有效期。
- 无记录展示“暂无邀请记录，分享海报邀请好友了解课程”；加载失败提供重试；未符合条件展示可理解的原因，不展示内部跟进笔记。
- 只允许查看当前登录学生归属的邀请和奖励。匿名访问、完整手机号、其他学生线索不对邀请人开放。

### 3.3 奖励明细

- 邀请详情进入对应奖励明细；展示奖励来源、类型、数量、状态、到账对象、有效期和适用产品。
- 待发放显示“邀请已确认，奖励待发放”；发放中显示“奖励发放中”；失败显示“奖励处理中，请稍后查看”，后台保留具体原因。
- 已到账赠堂支持进入已有课时账户查看；家长关联多个孩子时必须展示实际到账学生，到账规则见 D04。
- 首期沿用页面内状态和轻提示，不新增强制短信、邮件或 App 推送。

### 3.4 咨询承接页

- 分享链接或二维码打开 H5，无需先安装 App；展示活动说明、课程内容、咨询入口。可以引导打开 App，但留资链路不依赖安装完成。
- 咨询表单包含联系人称呼、国家／地区代码、手机号、咨询课程及必要的个人信息使用说明；手机号验证方式由业务和研发确认。
- 提交前校验必填和号码格式；提交中按钮禁用，失败保留输入并允许重试。成功显示“咨询已提交，我们会尽快联系你”。
- 重复提交返回原咨询结果，不重复新增奖励资格。H5 成功页不暴露其他用户的历史咨询信息。
- 来源无效时显示活动通用内容，可正常咨询但来源记为未知；活动结束显示结束说明，是否允许普通咨询按活动配置，不能继续承诺活动奖励。

## 四、后台功能

### 4.1 赠课审核与订单

- 沿用“订单管理 → 分享赠课 → 赠课审核”，保留学生、学管、顾问、月份、上传时间、凭证、状态、赠课数量、审核备注、审核人和通过时间。
- 所属顾问后展示分享渠道，可多选 Facebook、Instagram、朋友圈、WhatsApp 筛选；审核状态为待审核、待赠课、已赠课、不可赠。
- 新海报记录自动审核，审核人“中文路后台”，时间为服务端实际处理时间；历史记录保留人工审核。
- 点击凭证查看该次海报快照大图；点击“查看”打开右侧详情，状态读取当前记录，不沿用上次打开的数据。图片或详情加载失败允许重试。
- 待赠课执行第二章产品及订单规则；已赠课可“查看订单”，缺订单时提示异常并允许重新查询。返回保留筛选条件。

### 4.2 赠课海报配置

- 赠课审核右上角保留“赠课海报配置”，弹窗展示列表；左上角新增、右下角关闭。
- 最多配置 20 张未删除海报，最多显示 10 张；显示分组在前、隐藏在后，支持同状态内拖拽排序，不允许跨状态拖动。排序失败回滚。
- 新增默认显示，编辑保留状态，表单不增加状态字段；已显示 10 张时阻止新增并提示先隐藏一张。已有显示海报时至少保留 1 张；仅剩 1 张显示海报时，阻止隐藏或删除并提示先启用其他海报。初始无素材或数据不可用时，App 展示空状态。
- 列表展示序号、图片、标题、分享赠堂数、配文、状态、备注、更新时间和操作；三横拖拽图标位于序号前。
- 标题必填且 ≤30 字；分享赠堂数必填，只能为 1 或 2；备注选填且 ≤100 字，仅后台可见。
- 支持默认配文和备选文案，学生选择海报后自动带入。文案编辑需版本记录；已有分享保留当时快照。
- **图片优化建议，待确认（D06）**：保留 JPEG/JPG/PNG，上传原图上限从 500KB 调整为 5MB；推荐 1080×1440（3:4），兼容已有 750×1800 长图。生成缩略图与分享图，原图完整预览，保留二维码安全区域。
- 上传展示实际宽高、文件大小、完整预览及校验提示；超过上限或格式错误不可保存，不自动裁切、不拉伸。压缩后须验证文字和二维码可读；二维码合成导致超限时提示重新处理，不发布不可识别图片。
- 图片新增必填，编辑不换图时保留原图；前后端均校验格式、实际文件类型、大小和尺寸，具体阈值按 D06 确认结果执行。
- 隐藏后停止展示，逻辑删除需二次确认，文案明确历史分享、邀请、赠课记录及快照不受影响；删除后不再用于新分享。
- 新增、编辑、状态切换、删除、排序均记录操作人、时间和变更内容；有未保存编辑时离开须确认。

### 4.3 邀请记录与咨询跟进

- 筛选支持时间范围、邀请学生、被邀请人、活动、海报、所选渠道、来源状态及邀请进度。
- 列表展示邀请学生及编号、被邀请人脱敏信息、首次提交时间、海报／文案版本、渠道、咨询进度、邀请有效性、奖励状态和跟进人。
- 详情侧栏展示来源内容快照、访问到咨询的时间线、关联线索及奖励记录；完整联系方式仅有线索权限者可查看。
- 可进入现有咨询线索处理跟进，结果同步返回本模块。无法复用现有系统时保留待接入项，不要求客服双重登记。
- 授权客服执行“确认为有效邀请／标记未符合条件”，保存原因和处理时间；来源补录或修改须单独权限。
- 列表按提交时间倒序分页；导出按当前筛选和权限执行，手机号脱敏策略与列表一致。

### 4.4 邀请奖励管理

- 活动配置可设资格条件、奖励内容、奖励有效期、发放方式、单人上限及启停；奖励数量与产品选择须满足对应活动规则。
- 列表按时间、邀请人、活动和发放状态筛选，展示资格依据、奖励内容、到账学生、订单及操作人。
- “发放”前确认奖励对象和数量；批量发放逐条返回结果，单条失败不重复发放已成功项。
- 发放成功回写订单与课时流水；失败展示原因，支持按原奖励记录重试；已发放记录仅可查看及发起受控纠错。
- 非赠堂类福利须有对应到账依据，未确定发放渠道前不可用手动勾选“已发放”替代实际到账。

### 4.5 周统计与内容效果

- 默认本周，可按周／自定义日期、活动、邀请人、海报及渠道筛选；建议周一 00:00 至下周一 00:00，起点含、终点不含。
- **当周已分享用户**：当周至少一次成功调起分享的学生去重数；明细列学生、分享次数、首次／最近时间、海报与渠道。页面标注“按成功调起分享统计”。
- **当周分享用户所获赠堂**：以当周分享事件产生的奖励为一组，分别显示应赠、已到账、待到账堂数，允许在后续周继续更新到账结果。
- **当周实际赠堂数**：按成功到账时间统计，包括此前周分享或邀请产生、本周到账的奖励；分别显示分享赠堂、邀请赠堂和合计。不可把这项与前项视为同一指标。
- **内容效果**：链接访问次数、匿名访客去重数、咨询提交人数、有效邀请人数；按海报和文案版本追溯。匿名访客按可用浏览器标识估算，不保证跨设备识别同一人。
- 咨询人数按首次提交时间、有效邀请人数按有效确认时间统计；另提供“本周新增咨询后续结果”查看同一批咨询的有效及奖励情况。
- 同一被邀请人在同一活动重复提交只计一次咨询；重复回调不增赠堂；来源未知单列，不能归给任意邀请人。
- 分渠道／海报用户数相加可能大于全局去重人数；全局汇总重新去重。零记录显示 0，数据加载失败显示失败提示，不能显示为 0。
- 导出携带筛选条件、时区、统计区间、生成时间和统计口径；列表、汇总与导出从同一筛选数据计算。

## 五、权限、兼容与异常

| 范围 | 要求 |
| --- | --- |
| 学生与家长 | 仅访问本人学生账户的邀请、奖励与可分享素材；奖励详情显示实际到账学生 |
| 客服／学管 | 按线索权限查看联系方式、确认有效性；无奖励权限不可发奖 |
| 运营 | 配置素材及活动、查看效果；发奖和来源修改分别授权 |
| 管理员 | 查审计、授权纠错；不能删除历史奖励流水掩盖误发 |
| 历史素材与订单 | 缺赠堂配置默认 1；缺来源显示历史未记录；不推测补造邀请人 |
| 旧版 App | 服务端继续月度去重；无法展示 2 堂或来源链接的版本须限制新配置曝光或要求升级，最低版本待研发确认 |
| 数据一致性 | 服务端统一判断资格、订单与到账；奖励重试和批量操作不得重复扣额度或加课时 |
| 性能 | 沿用海报首屏、后台配置列表首屏不超过 3 秒目标；缩略图和大图分别加载，图片使用受控对象存储或 CDN |
| 保存与权限错误 | 防重复提交、保留用户输入；无权限不返回受保护字段；页面提供明确原因或重新登录 |
| 分享平台 | 按平台接入能力回传调起和发布结果；能力未知时标记未确认，不补造成功 |

## 六、业务示例

1. **月度资格**：学生本月首次调起海报 A（赠 1 堂），产生 1 堂资格；随后调起海报 B（赠 2 堂），仅新增分享记录，不补赠 1 堂。
2. **两堂产品筛选（按 D01 建议）**：本月首次分享赠 2 堂，产品 A 剩余赠课 1、产品 B 剩余赠课 3，且 B 未过期并有同校区同分钟赠堂产品，则仅 B 可选；到账后 B 已获赠 +2、剩余赠课 −2。
3. **跨周统计**：周日调起分享产生 2 堂奖励，周一到账。上周分享用户所获赠堂记录更新为已到账 2；本周实际赠堂数增加 2，不重复增加上周分享人数。
4. **邀请归属（按 D03 建议）**：新用户从学生甲的有效链接提交咨询，再从乙的链接重复提交，保留甲的首次归属；乙不产生该用户邀请奖励。
5. **发放重试**：奖励已经入账但前端等待超时，重试返回原奖励及原订单，课时不再增加；App 刷新后显示原到账结果。
6. **历史内容**：海报改名或删除后，历史邀请详情仍展示分享当时海报、文案及来源，不换成最新素材。
