# 分享与邀请业务流程

业务流程 · V2.0 · 更新日期 2026-10-27

分享赠堂和邀请奖励分别判断资格，共用来源内容及最终到账记录。规则以[PRD](海报分享赠堂-PRD.md)第二章为准，接口见[接口说明](接口说明.md)。

## 1. 分享赠堂

| 节点 | 执行方与动作 | 条件／去向 |
| --- | --- | --- |
| S1 | 用户选择海报和配文，系统生成专属链接及二维码海报 | 成功→S2；素材不可用／生成失败→重选或重试 |
| S2 | 用户发起社交分享 | 调起成功→S3；未安装／失败→保存或复制后手动分享，不占资格；仅保存也不占资格 |
| S3 | 系统记录已调起分享 | 当月首条→S4；非首条→结束，仅保存记录 |
| S4 | 系统按海报数量N自动审核并筛选产品 | 满足确认后的产品额度规则→S5；无有效产品／额度不足／无匹配产品→不可赠 |
| S5 | 系统创建赠送订单并完成付款确认及入账 | 全部成功→S6；失败→保留待赠课，后台按原奖励重试S5 |
| S6 | 用户查看已赠课及订单 | 赠送课次N、已获赠+N、剩余额度−N；统计归入实际到账时间 |

海报N可为1或2；单产品额度不足的处理采用PRD D01评审结果。调起后取消发布不撤销已有月度资格。真实发布结果另存，不作为社媒曝光量。

## 2. 邀请与奖励

| 节点 | 执行方与动作 | 条件／去向 |
| --- | --- | --- |
| I1 | 新用户点击链接或扫描二维码 | 来源有效→保留来源进入I2；无效→普通咨询页、来源未知；活动结束→显示结束说明 |
| I2 | 新用户填写并提交咨询 | 校验通过→I3；失败→保留输入重试；未提交→只记匿名访问 |
| I3 | 系统识别客户、去重并确定归属 | 新线索→I4；已有线索→返回原提交结果，不重复生成资格；归属冲突按D03 |
| I4 | 客服按活动规则确认邀请有效性 | 有效→I5；不符合→记录原因，App同步未符合条件；待核实→保持已提交咨询 |
| I5 | 系统按活动版本判断奖励资格与上限 | 满足→待发放并进入I6；不满足→不予发放并记录原因 |
| I6 | 授权运营确认发放福利 | 发放中→订单及课时服务；失败→保留原奖励记录重试；全部成功→I7 |
| I7 | App显示奖励到账，后台可查流水 | 赠堂进入指定学生课时账户；统计按实际到账时间入周 |

I3归属、I4门槛、I5奖励内容、I6发放方式为PRD D02–D05的建议方案，评审后确定。未确定前活动可保存草稿，不开启奖励发放。

## 3. 跨端回写与异常

- App查看邀请：I3成功后可见脱敏咨询记录；I4后刷新有效性；I7后刷新已到账。无来源咨询不进入任意学生的邀请列表。
- 后台改来源：授权人员提供依据并留痕；已经发奖时进入纠错，不自动为新邀请人追加奖励。
- 海报下架：阻止S1新的分享内容；I1已有链接按活动时效承接，历史图片及文案快照不替换。
- 服务超时：S5和I6先查询原交易结果，再按原记录继续；重复回调只更新原流水。
- 咨询跨周：I3计入咨询提交周，I4计入有效确认周，I7计入到账周；同一批咨询的后续结果可单独追踪。

## 4. 对应验收

S1–S3对应FR01–04、FR07；S4–S6对应FR05、FR10、FR12；I1–I3对应FR07–09；I4–I7对应FR09–11、FR13。失败、重复、来源未知及跨周路径对应FR14及第六章示例。全部待验收。
