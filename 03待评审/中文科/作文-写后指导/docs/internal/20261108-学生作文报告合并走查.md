## 2026-11-08 原型目录盘点

### 当前已覆盖的写作指导相关功能

- 教师后台发布任务：作文题目、题库选择、作文要求、年级、字数、班级、上传方式、反馈开关。
- 任务管理：任务列表、任务详情、提交进度、写作指导完成状态、学生写作情况和作文报告入口。
- 作文报告：写作指导记录（审题立意、选材构思、结构表达、完整指导）、作文原稿图片/文字、评分评语、批改信息；写后指导保留“待上线”状态。

### 与最新待评审 PRD 的差异

当前目录对应的是教师后台和静态报告展示，尚未形成完整的“学生端写前指导”原型。以下内容仍缺失或只有文案占位：

1. 学生端互动式审题拆解、启发式追问、角度整理、大纲构思和词句参考。
2. 禁止输出完整范文/完整段落/直接成文的前端提示与结果校验。
3. 日常任务、专项任务、评估/模考任务的指导权限和接口层开关。
4. 初稿 AI 预审的无分数反馈、多轮版本、差异对比和教师查看迭代轨迹。
5. 教师指导材料的生成、编辑、导出及命题作文/实用文模板区分。
6. AI 调用次数、缓存、异常、日志和版本持久化等可验收状态。

### 顶部学生端等页面消失的原因

`legacy-backend-bridge.js` 当前仅识别空 hash 或 `#/backend`，并在挂载时执行 `root.innerHTML = shell`。这会整体替换 `中文作文.html` 原有单文件应用的根节点，只保留教师后台壳；`打开原型.html` 又固定跳转到 `#/backend/publish-essay`，因此没有学生端入口，也没有学生端路由可以继续渲染。

这不是单纯的样式隐藏，而是入口和渲染层被兼容桥接层截断。原型同时存在旧版 `中文作文.html`、桥接脚本、独立 `writing-report/index.html` 以及顶层报告脚本，导致页面、数据和路由存在多套来源。

### 当前需优先解决的问题

1. 明确唯一主入口：教师后台、学生端、作文报告不能继续由旧单文件、桥接层和独立报告页分别持有一份路由。
2. 确认学生端最新来源并接入；在此之前，教师端的“写前指导”只能证明开关和静态报告展示，不能证明学生流程已走通。
3. 统一作文报告数据源；`writing-report/` 与主后台报告脚本不能继续双份维护。
4. 清理旧“新增作文题库”身份、旧版顶部栏和旧菜单文案，避免首次加载时出现需求名称闪烁或误导。
5. 全站繁体文案、教师后台简体占位文案和需求标识需统一后再做最终验收。
6. 重新执行旧版单文件构建/发布同步，确认动态加载的桥接脚本和报告数据文件在发布目录可用。

### 当前仍未完成的统一数据链

页面和路由已恢复，但学生端保存、教师任务管理、作文报告目前仍存在原型数据源分离：

1. 学生端提交主要写入 `writingGuideSubmissionsV1` 本地快照。
2. 任务管理仍以 `task-management.js` 的任务／学生模拟数据计算完成数和状态。
3. 作文报告仍由 `teacher-progress.js`、`writing-report-essay-data.js` 和 `writing-report-score-data.js` 读取报告模拟数据。

下一步必须建立唯一的提交记录契约，以 `taskId + studentId + submissionId` 关联写前指导快照、作文提交状态和报告；任务管理和报告均从同一记录读取，不能继续分别维护状态。验收顺序应为：学生保存成功 → 任务管理完成数与学生状态更新 → 学生写作情况进入对应报告 → 报告中的四步指导与学生保存快照一致 → 刷新和重复提交保持同一提交编号并去重。
