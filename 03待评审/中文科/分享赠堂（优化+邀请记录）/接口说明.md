# 分享赠堂接口说明

接口草稿 · V2.0 · 更新日期 2026-10-27

支持海报分享、咨询溯源、邀请资格与奖励到账的跨端协作。业务规则以[PRD](海报分享赠堂-PRD.md)为准。

## 1. 确认状态与依赖

本文件为建议契约，待研发确认；未取得现有 API、客服系统和课时账户接口资料。方法、路径、真实字段及错误码均未确认，下列名称为能力标识，不表示已实现端点。

学生端、后台原型仍为原 V1.x 静态页面；本轮只更新需求文档。H5、邀请列表、奖励、来源服务未接入，既有 HTML 中的平台页为页面展示，不是社媒 SDK 的接通证据。

## 2. 接口能力清单

| 标识／关联需求 | 调用方 → 提供方 | 处理与主要输入 | 返回与时机 | 变化建议 |
| --- | --- | --- | --- | --- |
| API01／FR01–06 素材 | App、后台 → 素材服务 | 读取／保存海报、配文、分享赠堂数及版本 | 素材列表、总数、图片信息、配置版本；进入页面或保存时 | 扩展现有能力 |
| API02／FR07 分享内容 | App → 来源服务 | 海报版本、文案、渠道、请求唯一标识；邀请人从登录态取得 | 来源标识、分享链接、二维码海报、内容快照 | 新增建议 |
| API03／FR03 分享事件 | App → 分享服务 | 分享标识、调起结果、发布结果及事件唯一标识 | 分享记录、当月奖励资格、资格数量或不发放原因 | 扩展；不信任客户端奖励数量 |
| API04／FR07 访问与活动 | H5 → 来源服务 | 来源标识、匿名访问标识 | 活动展示、可咨询状态、来源有效性 | 新增建议 |
| API05／FR07–08 咨询提交 | H5 → 线索服务 | 来源标识、称呼、区号及号码、课程、验证凭据、提交唯一标识 | 线索编号、提交状态；重复提交返回原结果 | 优先复用现有线索并扩展来源 |
| API06／FR09 邀请查询 | App、后台 → 邀请服务 | 筛选、分页；App 仅限当前学生 | 列表、脱敏对象、邀请进度、奖励进度、内容快照 | 新增建议 |
| API07／FR08、13 资格与归属 | 后台 → 邀请服务 | 记录编号、目标结果、理由、版本号；改归属附证据 | 更新后状态、处理人及时间、待发奖励编号 | 新增；资格与来源修改分别鉴权 |
| API08／FR10、13 邀请发奖 | 后台 → 奖励服务 → 订单／课时服务 | 奖励编号、版本号、操作唯一标识 | 发放状态、数量、到账学生、订单及课时流水 | 新增编排，订单及课时能力拟复用 |
| API09／FR09–10 奖励查询 | App、后台 → 奖励服务 | 奖励编号或筛选、分页 | 类型、数量、状态、原因、到账时间、有效期及关联订单 | 新增建议 |
| API10／FR11 统计导出 | 后台 → 统计服务 | 起止时间、时区、维度筛选、统计口径 | 人数、次数、堂数、生成时间；导出任务或文件 | 新增建议 |
| API11／FR04、10 活动配置 | 后台 → 活动服务 | 资格、奖励、范围、上限、有效期、版本及启停 | 草稿／启用状态、校验问题、版本号 | 新增建议；未决规则不能启用发奖 |

## 3. 建议字段与数据边界

全部字段名、类型与枚举为建议，业务语义须在研发评审时映射到现有模型。

| 对象 | 字段建议 | 类型／必填／校验 | 来源与用途 |
| --- | --- | --- | --- |
| 海报 | poster_id、poster_version、title、image_url、width、height、file_bytes | string/string/string/string/int/int/int；必填，标题≤30字 | 素材服务生成版本及资源信息 |
| 海报 | share_reward_lessons、default_copy、copy_options | int 必填且为正整数；string、string[]选填 | 历史缺数量默认1；配文字数按D06 |
| 内容 | share_id、activity_id、poster_version、copy_snapshot、selected_channel | string；除文案可空外必填 | share_id由服务端生成，文案保存实际分享版本 |
| 内容 | share_url、composed_image_url | string；必填，资源生成成功后返回 | 短链与二维码关联同一share_id；生成失败不可返回半成品 |
| 分享事件 | event_id、share_id、launch_result、publish_result | string；必填，发布未知为unconfirmed | 调起枚举opened/failed；发布枚举confirmed/unconfirmed/cancelled/failed |
| 咨询 | submission_id、country_code、phone、contact_name、course_id | string；必填，区号+号码归一化 | 身份验证方案按D02；日志与普通查询不暴露完整号码 |
| 咨询 | source_token、verification_token | string或null | 无来源可普通咨询；需验证时凭据必填 |
| 邀请 | invitation_id、lead_id、inviter_student_id、submitted_at | string/string/string或null/ISO时间；系统生成 | 来源未知时邀请人为null，不填虚构用户 |
| 邀请 | qualification、reason、record_version | enum/string或null/int；状态及版本必填 | submitted/qualified/ineligible；拒绝时原因必填 |
| 奖励 | reward_id、reward_type、quantity、recipient_student_id、rule_version | string/string/int/string/string；必填 | 数量>0，到账对象不可由普通App任意指定 |
| 奖励 | grant_status、order_id、ledger_id、credited_at、expires_at | enum，其余string或null | pending/processing/credited/failed/rejected；到账前订单及流水可空，credited必须有到账凭据 |
| 统计 | metric_basis、from、to、timezone、filters | string/ISO时间/ISO时间/string/object；必填 | occurrence_cohort或credited_period，区间左闭右开 |

分页建议 page_size 默认20、上限100，cursor首次为空；返回 items 数组和 next_cursor（无下一页为null）。列表无记录返回空数组，合法总数为0，不能用空值代替0。按业务时间倒序、编号倒序稳定排序。

## 4. 请求与响应示例

以下为虚构示例，非真实用户或可调用地址。

创建分享内容（API02）：

```json
{"poster_id":"P001","poster_version":"v2","copy_snapshot":"了解中文课程","selected_channel":"wechat","request_id":"req-demo-001"}
```

```json
{"share_id":"SH-DEMO-001","share_url":"https://example.invalid/s/opaque-token","composed_image_url":"https://example.invalid/media/SH-DEMO-001.png","share_reward_lessons":2}
```

查询邀请（API06，学生会话自动限定范围）：

```json
{"page_size":20,"cursor":null}
```

```json
{"items":[{"invitation_id":"INV-DEMO-001","invitee_label":"李** · 尾号1234","submitted_at":"2026-10-27T09:10:00+08:00","qualification":"qualified","reward":{"reward_id":"R-DEMO-001","quantity":1,"grant_status":"pending","credited_at":null}}],"next_cursor":null}
```

示例奖励1堂仅说明字段，不确定邀请奖励数量；实际值按D04通过后的活动规则。

## 5. 鉴权、错误与重试

- App 使用当前登录态确定学生范围，后台逐能力校验权限和记录数据范围；H5不返回邀请人手机号、其他客户资料或内部跟进笔记。
- API02 校验海报状态及版本；素材已下架时要求刷新选择，历史API06仍读取快照。
- API05 建议以国家代码和手机号及活动去重，重复提交返回既有结果；同一号码不得向未验证访问者暴露完整历史线索。
- API07 使用记录版本防覆盖；状态已变时返回当前状态，客户端刷新后重新判断，不自动覆盖他人处理。客服确认重复请求只产生一个资格事件。
- API08 以奖励编号作为稳定业务幂等键；每个批量项独立返回结果。超时先查询状态，重试复用原订单；订单已成功但课时未入账时继续原任务，不能再创建赠送订单。
- 发奖中不允许改到账学生、数量或规则版本；部分下游成功时须保存各步骤结果，完成入账后才标credited。
- 建议错误类别：AUTH_REQUIRED（重新登录）、FORBIDDEN（提示无权限）、VALIDATION_ERROR（定位字段保留输入）、SOURCE_INVALID（普通咨询来源未知）、VERSION_CONFLICT（刷新状态）、REWARD_NOT_ELIGIBLE（显示原因）、PROCESSING（查询结果）、TEMPORARY_FAILURE（保留输入允许重试）。真实HTTP状态和错误码待研发确认。
- 日志记录操作人、时间、对象、请求编号和变更前后值；保留来源纠正及奖励冲正链，不覆盖历史流水。

## 6. 发布依赖与联调验收

建议先部署可兼容旧客户端的服务端字段、幂等和历史读取，再配置后台及H5，最后发布App入口；发奖开关在业务参数与联调完成后启用。具体最低版本、SDK、短链域名、短信能力、客服回写和课时接口均待研发提供资料。

| 场景 | 跨端预期 |
| --- | --- |
| 旧海报与旧App | 缺数量按1读取；不支持自定义赠课数量、短链或二维码的客户端按经验证的版本策略处理，旧订单仍可查 |
| 二次分享／跨平台 | API03只新增分享事件，不重复生成月度资格 |
| 二人邀请同一号码 | API05去重，API07遵守D03，App与后台看到同一归属 |
| 调起成功但未发布 | 分享资格按调起口径，publish_result不伪造confirmed |
| H5无效来源 | 可咨询，来源未知，不随机关联邀请人 |
| 发奖超时重试 | 同一reward_id只对应一次入账，App展示服务端最终状态 |
| 跨周到账 | cohort结果与到账期统计各归其期，导出与页面一致 |
| 隐藏／删除及越权 | 新分享拒绝下架内容，历史快照可读；跨学生访问被拒绝 |

现阶段仅完成契约草稿审阅，上述联调均待验证。


## 配置版本与生效契约

对应PRD 2.4；本节为待研发确认的接口约束，未代表正式服务已接入。

- 素材保存成功后发布同一版本的海报、文案及数量；读取接口返回版本标识，更新图片资源版本或缓存键。
- 生成分享和赠课资格时校验客户端配置版本；过期时返回需刷新及重新确认的结果，不能悄然套用新数量。
- 已生成分享快照、奖励及订单固定原版本；历史来源解析保留原邀请归因，读取当前有效咨询页。
- 仅历史缺数量字段默认1；已有合法正整数不按旧客户端能力降级。服务端按验证后的能力门槛限制不兼容请求，保持月度去重和幂等。
- 最低App版本、能力标识、缓存更新机制及升级提示错误码由研发确定。不得把本地存储同步视为跨设备实时发布。
