# 分享赠堂（优化＋邀请记录）

PRD · V2.2 · 更新日期 2026-10-30

用户选择海报和配套文案分享，通过专属短链接或二维码邀请好友咨询，并查看邀请明细。后台配置赠课数量、管理登记跟进，按日期和渠道查看分享及登记效果。

## 一、涉及端口 · 菜单 · 功能点

1. **运营后台｜学员管理 → 分享赠课**：赠课审核、赠课统计、邀请明细、邀请统计、登记列表、渠道统计。
2. **运营后台｜分享赠课 → 赠课海报配置**：维护图片、标题、分享文案、自定义赠课数量、显示状态及排序。
3. **学生 App｜账号 → 分享赠课 → 我的邀请**：左右滑动海报、复制含短链接的文案、分享或保存海报、查看个人邀请成果。
4. **新用户 H5｜专属短链接／海报二维码 → 课程咨询**：登记个人信息，成功后进入 WhatsApp 咨询。
5. **关联模块｜订单与课时账户**：承接既有分享赠堂；邀请福利的具体资格和发放规则由运营确认。

## 二、业务规则

### 2.1 月度分享资格

- 用户成功调起社交平台分享面板，记为一次“已调起分享”；是否在社媒实际发布，独立记录为“已确认发布／未确认发布／取消／失败”。调起成功不能用作社媒曝光或实际发布量。
- 保留每名学生每月首次成功调起分享生成一条赠课审核记录的规则，自动审核后进入“待赠课”；第 2 次及以后仅记录分享，不再产生当月分享奖励。跨平台共享该月资格。
- 调起失败、未安装平台、仅切换海报、仅保存图片或复制文案均不消耗月度资格。已经调起后取消发布，按现有调起口径不撤销已生成的资格；若改为实际发布后赠堂，须另行确定平台可验证方式及业务规则。
- 每张海报可配置分享赠堂数量 N，N 为自定义正整数（单位：节）；以当月首次符合条件记录对应海报的数量为准。后续换海报不补差、不追加当月资格。
- 历史海报缺少赠堂配置时按原 1 堂兼容；历史订单和已经生成的奖励保留原数量。编辑海报不回算旧记录。
- 分享记录保存学生、海报及文案版本、渠道、发生时间、调起结果与来源标识。月度去重以服务端学生身份和业务月份为准。
- 月和周均建议采用 Asia/Shanghai 时区；跨地区业务时区由运营确认后统一用于页面、统计、导出。

### 2.2 分享赠堂的产品与订单规则

- 学生须存在未过期已购产品，且存在同校区、同课时分钟数的赠堂产品。已购 45min 产品只匹配 45min；已购 30min、45min 可分别匹配对应时长。
- **配置数量超过额度的处理，待确认**：同一个已购产品的剩余赠课数须 ≥ N；不足时不拆分产品、不降为 1 堂，状态为“不可赠”，原因“剩余赠课数不足”。该建议影响产品筛选和订单数量，见第六章 D01。
- 符合条件的已购产品按剩余课次数从少到多排序，默认选择最少者。并列时建议按产品到期时间由近到远、再按产品编号升序；单选且切换取消原选中项。
- 赠堂产品沿用既有五种产品配置，名称为“分享贈堂-{课时分钟}”，适用校区取已购产品校区。90min 等无对等赠堂产品时不可赠。
- 订单确认默认值：订单类型“赠送”、交易类型“常规”、归属为所选已购产品所属顾问、来源“系统下单”、赠送课次 N，自动提交。
- 付款确认默认值：付款链接“后台自选”、付款类型“全款”、支付方式“线下汇款”、收款账户“赠送账户”、实际支付时间为处理时刻、备注为产品名称，金额 0。
- 创建订单、付款确认和课时入账全部成功后，状态为“已赠课”，所选已购产品已获赠课数 +N、剩余赠课数 −N。任一步失败保留“待赠课”，后台查看原因并重试；重试复用原订单和奖励，不重复赠堂。
- 无未过期产品、无对等赠堂产品、剩余赠课数不足分别显示对应不可赠原因。
- 订单列表新增支付成功的赠送订单，隐藏编辑按钮；详情购买课次数为 0、赠送课次为 N，展示学生、产品、归属、支付信息和关联奖励记录。
- 历史上传凭证的待审核记录保留人工审核能力；历史凭证、订单和快照继续可查。


### 2.3 邀请归因与福利边界

- 专属来源关联邀请人、海报及文案版本、分享渠道、进入方式；登记成功后保留这些信息，支持查看是谁分享了什么内容及带来的登记效果。
- 链接与二维码指向同一咨询登记页；进入方式分别记为链接、扫码。只扫描但未打开页面不计扫码进入。
- 渠道按分享时的选择归因，内容转发后保留原来源，不自动识别最终转发平台。
- 未选择渠道直接复制文案，归为“复制文案／渠道未知”；不可强行归入某一社交渠道。该类来源的后台筛选呈现见待确认项。
- 来源缺失或无效时允许普通咨询，记录为未知来源，不伪造邀请人。历史记录保留当时的内容快照。
- 邀请福利与每月分享赠堂分别处理；海报配置的赠课数量不自动作为邀请奖励数量。访问、扫码或登记成功均不直接代表已获得福利。
- 用户可查看本人邀请成果与被邀请新用户明细；新用户定义、归属冲突、奖励条件、数量及发放方式见第六章。

### 2.4 版本兼容与配置生效

以下为配置生效及兼容的需求规则，最低支持版本与旧版限制策略须经研发验证后确认（D11）。

| 场景 | 生效时机与处理 |
| --- | --- |
| 后台新增或修改海报、文案、赠课数量 | 服务端保存成功后对新的读取请求生效；保存失败不发布新配置。后台列表更新为保存结果 |
| 新版App重新进入或刷新分享页 | 拉取最新配置，更新海报、文案及赠课数量；常驻已打开页面不承诺无刷新实时推送 |
| 用户停留页面期间后台改了配置 | 生成分享内容或提交赠课资格前校验配置版本；发现变化时提示刷新并让用户确认新海报及数量，不按过期显示静默发奖 |
| 尚未生成赠课记录 | 以服务端校验后确认的配置版本及数量生成记录；数量与该次分享内容保持一致 |
| 已生成的待赠课、已赠课记录及订单 | 固定该记录创建时的配置快照，不随后续修改增减数量，不回算历史订单或课时 |
| 已保存、已发出的海报及文案 | 不远程替换已有图片、二维码、文字或短链接；历史来源仍指向当时邀请人及内容版本 |
| 历史链接再次被打开 | 保留原归因；读取当前咨询页。海报隐藏或改图不等于历史链接失效，活动结束或链接失效按对应规则提示 |
| 历史海报缺赠课数量字段 | 仅缺字段时按原1节兼容；不能把已配置的其他数量降为1节 |
| 旧版App支持新数量及来源字段 | 能力经验证后可读取兼容配置；是否支持不能只根据版本名称推断 |
| 旧版App无法展示或正确处理新数量、短链接、二维码 | 建议提示升级，并阻止通过不兼容入口生成新配置的分享或赠课资格；不出现显示1节却按其他数量赠课的情况。既有订单和历史记录保留查询 |

- 服务端统一控制月度去重、配置版本、赠课数量和幂等；客户端升级、跨设备操作或切换海报不重置已用资格。
- 图片、文案和数量按同一配置版本发布，缓存更新不可把新图片与旧数量拼接展示。
- 后台配置保存生效不等于所有安装版本即时具备新功能；渠道统计、邀请明细、自动短链接及新版展示须满足对应端能力要求。
- 海报图片自动压缩适用于新增或重新上传的图片，不自动重压历史已分享海报。

## 三、需求内容

### 3.1 后台数据统计

- 赠课统计增加日期区间，默认当周，提供“当周”快捷恢复；按周查看当周已分享用户与实际赠出的堂数。开始日期不得晚于结束日期。
- 学员姓名、学员编号、所属学管、所属顾问、剩余赠课数继续支持筛选。
- “当月分享状态”使用已分享／未分享单选，直接点选；该条件判断当月状态，不能随日期区间悄然改为“当期分享状态”。
- 列表展示学员姓名、编号、学管、顾问、剩余赠课数、当期已获赠课数、最近分享月份、已过期赠课数、可获赠课总数及查看已赠操作。
- 当周已分享用户按成功调起分享的学员去重；不能把分享面板调起当作社媒实际发布或曝光。筛选、列表与导出使用相同数据范围。
- 零结果显示0；查询失败明确提示，不用0代替失败。

| 字段 | 统计口径 | 筛选联动 |
| --- | --- | --- |
| 累计已获赠堂数 | 用户历史所有已赠堂数累加，跨月不归零；顶部展示全部学员历史汇总 | 固定历史累计口径，不随页面筛选变化；新增实际赠堂后正常累加 |
| 当期已获赠堂数 | 筛选区间内实际赠出的堂数，按成功到账时间计入；列表文案为“当期已获赠课数” | 随筛选条件联动 |
| 剩余、已过期、可获赠课总数 | 沿用学员产品额度口径 | 顶部额度汇总不随下方筛选变化 |

当期数量是历史累计的区间切片，不能代替历史累计参与产品总额度等式。界面中既有“已获赠课数”卡片与新增累计指标的关系见D08。

### 3.2 分享海报展示

- 海报左右滑动切换，当前海报居中，两侧露出相邻海报并略缩小，形成叠加层次；指示圆点随选中项同步，不自动轮播。
- 沿用现有海报图片与内容，等比展示；去掉“本月分享海报”标题和圆点两侧独立箭头按钮。
- 顶部剩余赠课数与已获得赠课数紧凑展示，标签与数字同行；“我的邀请”置于右上角。
- 默认选择第一张显示海报，切换后同步海报、配套文案与专属链接。
- 生成分享海报时默认在左下角嵌入二维码，保持可扫码识别；二维码不得裁掉。保存的是包含二维码的当前海报。
- 操作入口顺序为 Facebook、Instagram、朋友圈、WhatsApp、保存。无法直接携带文案的平台，提供复制文案后分享的方式。
- 无可用海报显示空态，图片加载失败可重试；分享失败不消耗月度资格。

### 3.3 海报赠堂配置

- 每张海报独立配置赠课数量，使用数字输入框，输入大于0的整数，单位“节”；空值、0、负数及小数不可保存。默认1节，不限制为1–15节下拉。
- 保存后列表同步展示数量；编辑不回算已生成的赠课记录，缺配置的历史海报按1节兼容。
- 标题必填、最多30字；分享文案最多300字，可自动配文后编辑；备注用于后台说明。
- 保留新增、编辑、显示／隐藏、删除及同状态内排序能力；最多20张、同时显示最多10张，保留至少1张显示海报的既有规则。
- 图片新增必填，编辑不换图保留原图；保存失败保留输入，取消编辑不写入。历史来源快照不随海报修改或删除而丢失。

### 3.4 海报图片优化

- 支持 JPEG、JPG、PNG；大于1MB自动压缩至1MB以内，不超过1MB保留原图。
- 推荐尺寸750×1800px；压缩保持原比例，不裁剪、不拉伸，保证文字清晰和二维码可识别。
- 处理完成展示预览、实际尺寸及文件大小；处理中禁止提交，失败提示重新上传。
- 原图与最终分享图均应清晰可读；若无法兼顾体积和识别效果，不静默发布低质量图片，提示重新处理。

### 3.5 路径、短链接与渠道统计

**自动生成与进入路径**

- 选择海报和渠道后自动生成专属短链接，关联邀请人、海报及渠道；短链域名与跳转服务统一配置，后台无需为每张海报填写链接。
- 二维码与文字短链接进入同一“课程咨询”页，并分别保留扫码／链接进入方式。
- 咨询页顶部有返回按钮和居中标题，品牌标识及介绍居中；展示联系人称呼、国家／地区代码、电话号码、孩子年龄、学习需求和信息使用同意项。
- 姓名、电话、年龄与同意项必填；学习需求选填。提交前校验，提交中禁止重复点击，失败保留资料并允许重试。
- 成功后显示“提交成功”及即将进入 WhatsApp 的说明；倒计时3秒自动进入咨询页，同时保留立即进入按钮。离开成功页或手动进入后取消倒计时，避免二次跳转。
- 咨询内容携带本次课程及登记信息供用户确认后发送；页面跳转不等同于消息已发送或客服已回复。

**渠道统计**

- 在登记列表右侧设置独立渠道统计Tab。筛选：日期（默认当周）、渠道、海报、邀请人；顶部汇总及列表随查询条件同步变化。
- 渠道与App入口一致：Facebook、Instagram、朋友圈、WhatsApp、保存。“保存”统计保存海报后扫码带来的访问及登记，不是保存按钮点击次数。
- “查看登记明细”沿用当前渠道及其他筛选条件，显示登记人、联系方式、邀请人、海报来源、登记时间及跟进状态。

| 指标 | 口径 |
| --- | --- |
| 访问次数 | 落地页成功打开次数，重复打开累计 |
| 访问人数 | 区间内按访客标识去重 |
| 扫码进入人数 | 扫码后成功打开落地页的去重访客数 |
| 链接进入人数 | 通过文字链接打开落地页的去重访客数 |
| 登记人数 | 区间内成功提交登记并去重的人数 |
| 登记转化率 | 登记人数 ÷ 访问人数 × 100%，展示1位小数；分母为0时展示“—” |

跨渠道、跨进入方式可重复出现同一访客，汇总重新去重，不能直接累加分组人数。访客识别与登记去重的跨设备合并规则见D09。

**登记列表与跟进**

- 登记列表位于邀请统计右侧，汇集成功提交的资料，字段包括登记人、联系号码、孩子年龄、学习需求、邀请人、海报来源、登记时间、跟进状态及备注；详情保留渠道和进入方式。
- 支持登记人／号码、邀请人和跟进状态查询、重置；查看详情可更新状态及备注。
- 状态为待跟进、已联系、跟进中、已完成、无效；新登记默认待跟进。备注最多500字。
- 保存后列表与详情一致，刷新保留；保存失败保留编辑内容。跟进状态不自动等同于邀请奖励资格。

### 3.6 海报配套文案

- 后台自动配文后可编辑保存，App随所选海报展示对应文案。
- 系统将专属短链接自动追加到文案末尾，点击复制时一并复制文案与链接；无需后台填写链接。
- 切换海报或渠道同步更新对应文案及专属链接；分享到不同渠道时使用当前内容。
- 无文案时提供填写或重新配文入口；复制失败提供长按复制提示。自动配文是否使用AI不作为已确定的实现方式。

### 3.7 邀请明细与福利赠送

- App右上角“我的邀请”展示本人邀请成果及被邀请新用户明细；后台邀请明细查看邀请人、被邀请人、内容来源、渠道及时间。
- 后台邀请统计按邀请人汇总参与邀请人数、邀请新用户数，展示邀请人成果及最近邀请时间，可查看明细；不展示发起咨询人数和咨询转化率卡片。
- App展示脱敏被邀请人资料；后台完整联系方式按权限控制，内部跟进备注不对邀请人展示。
- 邀请人可据有效邀请获得福利，福利规则确认后执行；条件、数量、上限、到账对象、有效期及发放方式不得由海报分享数量自动推导。
- 福利发放应有可追溯记录，只有实际到账后显示已到账；失败重试不得重复发放。细化发放状态与操作入口待规则确认。

## 四、业务示例

1. 学员累计已获赠12节，当前周到账2节：累计显示12、当期显示2；切换至另一区间，累计仍为12，当期按该区间重算。
2. 海报A配置3节，海报B配置18节，两者保存后各自列表显示对应值；输入0或1.5时阻止保存，不更改原值。
