## 一、需求背景

原流程中，学生在普通话 App 通过选择本地图片进行分享，分享凭证还需学管人工审核。该方式存在以下问题：

- 学员需要自行准备或选择本地图片，操作门槛较高。
- 学管需要逐条审核分享图片，耗时耗力。
- 分享内容不统一，销售部无法稳定控制对外传播素材质量。
- 活动海报更换依赖人工通知，缺少可配置、可排序、可下架的统一管理入口。

销售部期望由后台统一配置分享海报，学生自主选择海报后直接分享到社交平台，从而减少人工审核成本并提升分享素材一致性。

---

## 二、需求目标

- 学生端：在「账号 / 分享赠课」中提供可选海报列表，学生选择海报后发起系统分享。
- 后台端：在「订单管理 / 分享赠课 / 赠课审核」右上角提供「赠课海报配置」入口，统一管理学生端可见海报。
- 运营端：支持活动海报按需新增、编辑、隐藏、删除和拖拽排序，最多添加 20 张，最多展示 10 张。
- 审核侧：新海报分享流程不再要求学生上传本地图片，降低学管逐图审核压力。
- 历史数据侧：保留已有分享凭证、赠课记录和海报快照追溯能力，不影响历史记录查看。

## 五、全局状态与权限定义

> 状态、权限与审计在此集中定义，功能详述中不重复展开。

### 5.1 状态定义

| 状态名称 | 前端表现 | 后台操作限制 | 触发条件 |
| :--- | :--- | :--- | :--- |
| 显示 | 学生端海报候选列表可见，按排序展示；最多展示前 10 张 | 可编辑、可隐藏、可删除、可在显示分组内排序 | 新增海报默认显示；后台从隐藏切换为显示 |
| 隐藏 | 学生端不可见；后台列表中位于显示海报之后 | 可编辑、可显示、可删除、可在隐藏分组内排序 | 后台从显示切换为隐藏 |
| 已删除 | 学生端不可见；后台有效配置列表移除 | 不可再编辑、显示或排序；历史记录保留快照 | 后台二次确认删除后逻辑删除 |
| 待审核 | 后台审核列表可见，等待人工审核 | 历史人工审核数据保留；新海报分享默认不再停留该状态 | 历史上传凭证或旧流程进入 |
| 待赠课 | 后台审核列表可见，操作列展示「去赠课」 | 系统校验未过期产品和剩余赠课数，满足条件后自动创建赠送订单 | 每月首条海报分享记录生成后默认进入 |
| 已赠课 | 后台审核列表展示赠课结果 | 仅可查看记录与订单结果 | 赠送订单创建并付款确认成功 |
| 不可赠 | 后台审核列表展示不可赠原因 | 不再创建赠送订单，仅可查看原因 | 不存在未过期产品或所有产品剩余赠课数均为 0 |
| 分享成功 | 生成成功分享记录，可参与赠课统计 | 记录关联海报 ID、海报标题快照、平台和学生 ID | 平台发布结果回传成功 |
| 分享取消 | 不发放赠课，可记录取消结果 | 不生成成功记录 | 用户在平台发布前取消 |
| 分享失败 | 不发放赠课，前端提示可重试 | 不生成成功记录或记录失败结果 | 平台回传失败、网络失败或系统异常 |

### 5.2 权限定义

| 权限项 | 适用角色 | 可执行操作 | 限制说明 |
| :--- | :--- | :--- | :--- |
| 学生端读取海报 | 学生、家长 | 查看显示状态海报、切换海报、分享、保存 | 仅可读取 `status=show` 且未删除的海报，不可访问隐藏或删除海报 |
| 赠课海报配置 | 销售/运营、后台管理员 | 新增、编辑、显示/隐藏、删除、同状态排序 | 需具备「订单管理 / 分享赠课 / 赠课海报配置」权限 |
| 分享赠课记录查看 | 学管、后台管理员 | 查看分享记录、赠课结果与历史快照 | 删除海报不影响已有记录追溯 |
| 操作审计 | 后台管理员、系统 | 记录配置操作日志 | 新增、编辑、显示/隐藏、删除、排序均需记录操作人、时间和变更内容 |

## 七、需求功能详述

### 7.1 学生App——分享赠课

**对应页面**：
- 前端：`index.html`，分享赠课页。
- 进入路径：账号页保留原「分享赠课」入口，点击后进入分享赠课页；账号入口不再作为本章独立功能节点。

**用户故事**：
> 作为一个学生或家长，我想要从后台配置的海报中选择一张并分享到社交平台，以便完成分享动作并获得赠课机会。

**前置条件**：
- 用户已登录学生 App。
- 用户可通过账号页原「分享赠课」入口进入分享赠课页。
- 后台存在未删除海报配置，学生端仅展示显示状态海报。


#### 7.1.1 选择海报

**核心逻辑**：
- 页面以一张大图展示当前选中海报，下方横向展示后台显示状态海报缩略图。
- 默认选中后台排序第一张显示状态海报；点击缩略图后，大图和后续平台携带图片同步更新。
- 学生端最多展示 10 张显示状态海报，按后台配置排序展示。
- 切换海报仅改变当前选中项，不生成分享记录，不消耗赠课机会。
- 点击保存时保存当前选中海报原图，保存动作不生成平台分享记录。

**后置条件**：
- 当前选中海报作为 7.1.2 分享社交平台的图片来源。
- 若用户离开平台发布页再返回分享赠课页，保留原海报选中状态。

**字段说明**：

| 序号 | 字段名称 | 类型 | 是否必填 | 字段长度 | 数据来源 | 数据区间 | 提示文案 | 其他 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | poster_id | 短文本/整数 | 是 | - | 海报列表接口 | 未删除且显示状态 | - | 当前选择海报 ID |
| 2 | title | 短文本 | 是 | ≤ 30 字 | 后台配置 | - | - | 学生端不在海报区右上角展示 |
| 3 | image_url | 附件（图片） | 是 | 单张≤500KB | 后台配置 | JPEG/JPG/PNG | 暂无可分享海报，请稍后再试 | 用于大图与缩略图 |

**边界条件与异常处理**：
- 无显示状态海报时，展示空状态「暂无可分享海报，请稍后再试」，不展示分享按钮或置灰。
- 海报图片加载失败时，当前海报展示加载失败占位，允许切换其他海报。
- 学生端接口返回超过 10 张时，仅展示前 10 张，仍按后台排序。
- 保存时浏览器或系统阻止下载，提示保存失败并允许重新点击保存。

#### 7.1.2 分享社交平台

**对应页面**：
- 前端：`index.html`，分享赠课页底部操作栏。
- 前端参考页：Facebook 新帖子页、Instagram 新帖子页、微信朋友圈发表页、WhatsApp 动态页、本地保存。

**核心逻辑**：
- 底部固定展示 Facebook、Instagram、朋友圈、WhatsApp、保存五个操作，按该顺序排列；每项图标在上、文字在下。
- 点击 Facebook、Instagram、朋友圈、WhatsApp 后，进入对应发布前确认页并携带当前选中海报。
- 分享成功判定。以用户点击社交分享按钮，且成功调起社交平台的分享面板为准,即 Facebook 进入帖子发布页，Instagram 进入新帖子发布页，朋友圈进入微信朋友圈发布页，WhatsApp 进入动态发布页。比如用户未安装 Facebook，提示：未检测到 Facebook，可复制海报或保存后手动分享。
- 每月第一条分享海报生成一条赠课审核记录；每月第 2 条及以后分享海报不生成赠课审核记录。由海报分享生成的赠课审核记录，其分享凭证为学生当前选择的海报快照，分享渠道为学生点击的平台渠道。
- 点击保存后触发系统文件保存/下载能力，文件名优先使用海报标题并保留原图片扩展名。

**平台发布页与保存规则**：

| 操作 | 目标页 | 携带内容 | 参考图 |
| :--- | :--- | :--- | :--- |
| Facebook | Facebook「新帖子」页 | 当前选中海报图 | `assets/facebook-帖子分享.jpg` |
| Instagram | Instagram「新帖子」页 | 当前选中海报图 | `assets/instagram-帖子分享.jpg` |
| 朋友圈 | 用户微信朋友圈发表页 | 当前选中海报图 | `assets/微信-朋友圈分享.jpg` |
| WhatsApp | 用户 WhatsApp 动态页 | 当前选中海报图 | `assets/Whatsapp-动态分享.png` |
| 保存 | 系统本地保存 | 当前选中海报原图 | 无 |

**字段说明**：

| 序号 | 字段名称 | 类型 | 是否必填 | 字段长度 | 数据来源 | 数据区间 | 提示文案 | 其他 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 分享渠道 | 单选 | 是 | - | 前端操作 | Facebook/Instagram/朋友圈/WhatsApp | - | 保存不写入该字段 |
| 2 | poster_id | 短文本/整数 | 是 | - | 当前选中海报 | - | - | 分享记录关联 |
| 3 | 海报标题 | 短文本 | 是 | ≤ 30 字 | 当前选中海报 | - | - | 分享时标题快照 |
| 4 | 分享时间 | 日期时间 | 是 | - | 系统生成 | `yyyy-mm-dd hh:mm:ss` | - | 分享发生时间 |
| 5 | 分享结果 | 单选 | 是 | - | 系统判断 | 已成功/未成功 | 分享失败，请重试 | 影响赠课统计 |


**边界条件与异常处理**：
- 社交平台打开失败时，停留在分享赠课页并提示稍后重试。

### 7.2 订单管理-分享赠课-赠课审核

**对应页面**：
- 后台：`admin.html`，订单管理 / 分享赠课 / 赠课审核。

**用户故事**：
> 作为学管或后台管理员，我想要查看学生分享海报记录并自动完成符合条件的赠课订单，以便减少人工审核和手动下单成本。

**前置条件**：
- 后台用户已登录。
- 用户具备「订单管理 / 分享赠课 / 赠课审核」的菜单权限。
- 每月第一条海报分享已生成赠课审核记录。

#### 7.2.1 赠课审核列表

**筛选项**：

| 筛选项 | 控件类型 | 选项/范围 | 说明 |
| :--- | :--- | :--- | :--- |
| 分享渠道 | 多选| Facebook、Instagram、朋友圈、WhatsApp | 新增筛选项，用于筛选不同平台分享记录 |

#### 7.2.2 自动赠课

**待赠课前置条件（均需满足）**：
- 当前学生存在未过期产品。
- 任一未过期产品的剩余赠课数 ≥ 1。

**核心逻辑**：
- 待赠课记录满足全部前置条件时，系统自动进入赠送订单创建流程；若不满足全部前置条件，则将审核状态修改为「不可赠」，并备注说明理由，比如产品剩余课次数不足，或者暂无有效期内产品可赠 或无可赠产品；
- 自动创建赠送订单时，系统自动读取该申请的学生编号并代入订单流程。
- 选择产品页的产品选项范围：
   1）系统收集该学生所有未过期产品，2）剩余赠课数≥ 1  
    3）上课时长对等：例子1：已购45min的产品，只能选择45min的赠堂产品。比例2：已购30min、45min的产品，可选对应的30min、45min的赠堂产品
- 优先选择：优先选择所购产品剩余课次数最少的对应赠堂产品。单选。
- 示例：张三已购产品 A（25min）、产品 B（25min）、产品 C（30min）、产品 D（45min），对应剩余赠课数为 2、1、0、3；对应的剩余课次数为5,3,2,1。 则产品 C 不予计算，选择产品页可展示45min、25min的赠堂产品，默认选择剩余课次数为最少的45min赠堂产品

- 产品名称按「分享贈堂-{课时分钟}」展示；适用校区取学生购买产品的校区。选择产品页严格参考 新增赠送订单-选择产品。
- 可选的分享赠堂产品见![分享赠堂产品](分享赠堂产品.png)，当前就5个。

- 订单确认页字段默认值：订单类型为「赠送」、交易类型为「常规」、订单归属为学生购买产品的所属顾问、订单来源为「系统下单」、赠送课次数默认代入 1，然后自动提交订单。订单确认页严格参考 新增赠送订单-订单确认。
- 付款确认页字段默认值：付款链接为「后台自选」、付款类型为「全款」、支付方式为「线下汇款」、收款账户为「赠送账户」、实际支付时间取当前系统背景时间、备注默认取产品名称。付款确认页样式与字段布局严格参考 新增赠送订单-付款。

**后置条件**：
- 自动创建赠送订单并完成付款确认后，审核状态更新为已赠课，赠课数展示 +1 课。学生购买的指定产品已获赠课数+1，剩余赠课数-1。比如张三海报购买A产品：普通话25min的课程，通过海报分享，获得1节25min的赠课，这个A产品已获赠课数+1，剩余赠课数-1。
- 已赠课后，需要在「订单管理 / 订单列表」新增一条赠送订单；订单状态为「支付成功」，订单类型为「赠送」，支付方式为「线下汇款」，支付金额为 0。已赠课订单操作列的编辑按钮隐藏。
- 不满足待赠课前置条件时，审核状态更新为不可赠，并保留不可赠原因。
- 审核记录保留分享凭证海报快照、分享渠道、学生编号、所属顾问、处理时间和订单结果。


**边界条件与异常处理**：
- 学生均为已过期产品时，待赠课记录自动更新为不可赠，原因：已过期产品不可赠。
- 学生所有未过期产品剩余赠课数均为 0 时，待赠课记录自动更新为不可赠，原因：剩余赠课数不足。
- 学生购买90min等产品，无对等上课时长的赠堂产品，待赠课记录自动更新为不可赠，原因：无可赠堂产品。

- 选择产品时剩余剩余赠课数为 0 的产品不展示为可选项。
- 选择产品时若用户切换产品，应取消原产品选中状态，确保页面始终只有一个产品被选中。
- 自动创建订单、提交订单或付款确认失败时，保留待赠课状态并提示后台重试。

#### 7.2.3 查看订单

**核心逻辑**：
- 已赠课记录的操作列增加「查看订单」，点击后打开订单详情；订单详情严格参考 `订单管理-订单详情`。
- 赠送订单在「订单管理 / 订单列表」中可查看，订单列表新增支付成功的赠送订单记录。
- 赠送订单在订单列表中隐藏「编辑」按钮，仅保留订单查看能力。
- 分享赠课生成的赠送订单详情中，购买产品表的「课次数」展示为 0，「赠送课次」展示为 1。
- 订单详情需展示订单状态、订单类型、支付方式、支付金额、产品名称、学员信息、订单归属和关联赠课审核记录。


**边界条件与异常处理**：

- 订单详情加载失败时，保留当前审核列表筛选状态并提示重试。

#### 7.2.4 赠课海报配置

**对应页面**：
- 后台：`admin.html`，订单管理 / 分享赠课 / 赠课审核 / 赠课海报配置弹窗。
- 后台：赠课海报配置弹窗 / 新增海报弹窗 / 编辑海报弹窗 / 删除确认弹窗。

**前置条件**：
- 用户具备订单管理 -分享赠课的菜单权限
- 用户具备海报配置的操作权限

**配置列表**：
- 赠课审核页面右上角展示「赠课海报配置」按钮；点击后以弹窗展示海报配置列表。
- 配置弹窗内展示未删除海报，显示状态海报在前、隐藏状态海报在后。
- 「新增海报」位于配置列表左上角，「关闭」按钮位于弹窗右下角。
- 配置列表展示序号、海报图片、标题、状态、备注、更新时间和操作。
- 序号左侧展示三横拖拽图标；按住图标可拖拽调整。

**新增/编辑海报**：

- 表单包含标题、海报图片、备注，不提供状态字段。
- 标题必填，不超过 30 个字。
- 海报图片新增必填，编辑时可不重新上传；支持 JPEG、JPG、PNG 格式，单张图片不超过 500KB；推荐尺寸宽 750px、高 1800px。
- 新增海报默认状态为「显示」；编辑海报保留原状态。
- 前端即时校验，后端必须二次校验。
- 保存成功后返回海报配置列表；显示状态海报会进入学生端候选列表。
- 最多新增20张海报，若总数超过20张，弹窗提示“当前最多可创建20张海报”

**显示/隐藏海报**：
- 操作列支持「显示 / 隐藏」切换。
- 状态由隐藏改为显示后，自动移动至显示分组；状态由显示改为隐藏后，自动移动至隐藏分组。
- 显示状态海报最多 10 张，超过上限时弹窗提示“当前最多显示10张海报，你可隐藏部分海报再试”
- 隐藏状态海报保留后台记录，但不在学生端展示。

**排序**：
- 支持在同一状态分组内拖拽表格行排序。
- 拖拽完成后即时更新页面序号并保存排序值。
- 显示状态固定排在隐藏状态之前，禁止将隐藏海报拖入显示分组前方。
- 显示状态和排序变化会同步影响学生端海报展示顺序。

**删除海报**：
- 删除操作需二次确认。
- 删除确认文案需明确：删除不影响已有分享记录、赠课记录及海报快照。
- 后端执行逻辑删除，保留历史记录关联、海报标题及图片快照和审计信息。
- 删除后仅从后台有效配置列表和学生端候选列表移除，不再用于新的分享。
- 已生成的分享记录、赠课结果和历史审核详情继续正常展示与追溯。

## 8 非功能要求

### 8.1 消息通知

本期不新增强制性的 App 推送、短信、邮箱或会员中心通知。页面内轻提示按以下规则处理：

暂无

### 8.2 性能要求

- 学生端海报列表首屏加载不超过 3 秒。
- 后台海报配置列表首屏加载不超过 3 秒。
- 图片需使用 CDN 或对象存储，支持压缩缩略图，避免直接加载后台原图私有路径。
- 缩略图与大图应分别使用适合尺寸的资源，降低移动端加载压力。
- 后台配置操作需防重复提交，避免短时间重复保存或重复排序。

### 8.3 安全要求

- **文件安全**：上传接口需校验 MIME、扩展名和文件大小；仅支持 JPEG、JPG、PNG，单张图片不超过 500KB。
- **访问控制**：仅具备「订单管理 / 分享赠课 / 赠课海报配置」权限的后台用户可新增、编辑、删除、排序海报。
- **数据隔离**：学生端仅可读取显示状态且未删除海报，不可访问隐藏或删除海报。
- **路径保护**：学生端分享行为不得暴露后台原图存储私有路径。
- **审计追溯**：显示/隐藏、删除、排序、新增、编辑均需记录操作日志，至少包含操作人、操作时间、操作类型、海报 ID、变更前后关键字段。
- **接口幂等**：新增、删除、排序和状态切换接口需防重复提交，避免重复记录和排序错乱。

### 8.4 兼容性要求

- 与历史分享凭证记录兼容：不删除历史分享凭证记录，历史记录仍可追溯。
- 与历史赠课记录兼容：删除海报不影响已有分享记录、赠课记录及海报快照。
- 与订单赠课数规则兼容：本期不改造订单赠课数计算规则。
- 与现有账号页兼容：账号页「分享赠课」入口保留，底部导航和账号页其他功能保持不变。
- 与既有审核流程兼容：学管仍可查看学生分享赠课记录和赠课结果，但新海报分享流程减少本地图片人工审核压力。
