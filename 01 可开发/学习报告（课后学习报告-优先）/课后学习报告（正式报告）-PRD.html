一、需求背景

教务管理后台已有「学习报告」菜单，用于老师或教务人员查看待发送、已发送的学习报告，并进入报告填写或详情查看。当前入口截图中，列表筛选项包含班级名称、上课时间、校区、授课老师、班级类型，但缺少按单个学生快速定位报告的能力；同时「班级类型」字段实际承载的是正式、试听课、转老师试听、阶段等报告类别，命名与业务含义不一致。

本次需求在不改变现有教务管理后台视觉框架的前提下，补齐学生姓名/ID筛选能力，统一「报告类型」命名，并新增「总结报告」类型，为正式报告、试听课报告、阶段报告及总结报告提供一致的列表筛选、填写、发送、查看和学生端展示链路。

二、需求目标

  1. 在教务管理-学习报告列表筛选区新增「学生姓名/ID」，支持按学生姓名或学生 ID 精准/模糊查询相关报告。
  2. 将筛选项「班级类型」统一改名为「报告类型」，字段语义与报告业务类型保持一致。
  3. 在「报告类型」中新增「总结报告」，并保证列表筛选、快捷标签、报告填写入口、发送状态和学生端展示链路可识别该类型。
  4. 保持入口页与参考截图一致的后台布局：左侧深色菜单、顶部标签页、白色筛选卡、待发送/已发送 Tab、1V1/班课切换、报告卡片列表和右侧操作按钮。
  5. 梳理正式报告、试听课报告、阶段报告、总结报告的后台填写/查看字段与学生端展示结构，形成可开发、可测试的需求闭环。

七、需求功能详述

7.1 学习报告列表

对应页面：

  • 后台原型：prototype/admin.html。
  • 前端位置：中文路 Web 后端 / 教务管理 / 学习报告。

用户故事：

作为一个学管或老师，我想要在学习报告列表中按班级、学生、时间、校区、授课老师和报告类型快速筛选报告，以便准确找到需要填写、发送或查看的学习报告。

前置条件：

  • 用户具备教务管理-学习报告的菜单权限。
  • 系统已根据课次、阶段节点或总结节点生成对应报告数据。

核心逻辑：

  • 筛选区在现有字段基础上新增「学生姓名/ID」输入框，支持学生姓名、学生 ID、登录账号模糊查询。
  • 原「班级类型」字段在页面文案、接口字段说明、导出字段和埋点口径中统一修改为「报告类型」。
  • 「报告类型」下拉枚举包含正式、试听课、转老师试听、阶段、总结报告；其中「总结报告」为本次新增独立类型。

后置条件：

  • 用户可基于筛选结果进入正式报告、阶段报告、总结报告的填写页或教师查看页。

字段说明：

序号 字段名称 类型 是否必填 字段长度 数据来源 数据区间 提示文案 其他
1 学生姓名/ID 短文本 否 ≤ 50 字 用户输入 已授权学生 请输入学生姓名/ID 支持学生姓名、学生 ID、登录账号查询；大小写不敏感
2 报告类型 单选 否 - 报告类型枚举 正式、试听课、转老师试听、阶段、总结报告 请选择报告类型 原「班级类型」更名；支持清空表示全部

边界条件与异常处理：

  • 学生姓名/ID输入空格时，查询前自动去除首尾空格；去除后为空则不作为筛选条件。
  • 输入不存在的学生姓名/ID时，列表展示空状态，不报错。
  • 报告类型选择「总结报告」但暂无数据时，展示空状态「暂无学习报告」。

7.2 正式报告

功能范围：

  • 覆盖正式报告的后台填写、教师查看和学生 app 查看。
  • 后台页面入口来自 7.1 学习报告列表；学生 app 页面入口来自「AI學情分析」报告列表。
  • 正式报告对应普通正式课课后反馈，报告类型展示为「正式」。

7.2.1 填写正式报告

对应页面：

  • 后台原型：prototype/admin.html。
  • 路径：中文路 Web 后端 / 教务管理 / 学习报告 / 填写正式报告。

用户故事：

作为一个授课老师，我想要为正式课学生填写课后学习报告并发送，以便学生和家长及时了解本节课表现和掌握情况。

前置条件：

  • 用户具备教务管理-学习报告的菜单权限。
  • 当前用户具备该班级或学生（1V1）的报告填写权限。

核心逻辑：

1.样式说明
  • 页面底部固定展示「发送报告」操作栏，用户滚动填写长表单时无需回到底部即可提交；点击后仍执行完整必填校验。
  • 报告填写页和查看页的右侧学生表随页面滚动吸附在可视区域内；名单较多时右侧区域内部滚动，表头固定展示姓名、发送状态、阅读状态、操作。
  • 右上角增加报告类型标识。
2.课程说明
  • 「课程名称」改为课次下拉搜索筛选控件，默认值来源当前学生信息-上课记录；收起态按「课程名称 / 课次 课次名称」展示，例如「港澳普通话_L1-L9_25m / 第14讲 小小導遊——香港 ao ou iu」。
  • 展开态参考上课记录筛选样式：顶部仅展示当前课程，不展示课次范围说明文案；中部提供搜索框，支持按课次、课次名称、课程名称模糊匹配；列表行展示课次、课次名称、上课状态（已结束、未上课），本课次显示蓝色「本课次」标签，已生成报告的课次显示绿色「报告已生成」标签；底部展示当前命中课次数。
  • 下拉展示当前学生当前课程中本课次前5个课次、本课次及后续全部课次；不足5个历史课次时展示实际已有课次。范围固定以进入填写页时的本课次为基准，切换所选课次不改变范围。系统按学生 ID + 课程名称 + 课次 + 课次名称判断是否已生成正式报告；已生成的课次保留展示并标记「报告已生成」，不可重复选择生成；仅「未上课」或「已结束」且未生成报告的课次可选。
  • 课次列表按课次数字从小到大排序，列表内部滚动展示后续全部课次。例如本课次为第14讲时，展示第9至13讲、第14讲及第15讲起的全部后续课次；搜索只在该范围内过滤。
  • 选择或更改「课程名称」后，系统根据所选课程、课次自动带出原有学习内容；学习内容默认来源课件管理-编辑课件-学习内容，见7.2.4。
3.学习内容
  • 学习内容为必填，不超过 200 字。输入框下方显示说明「每行一个学习内容，按Enter换行；空白行不会生成要点」及当前要点数、字数。
  • 老师修改学习内容后，页面提示掌握情况尚未更新；点击右下角「保存并更新掌握情况」后，系统按换行拆分学习内容，去除首尾空格并过滤空白行，将每个非空行更新为一条掌握情况内容。未点击更新前禁止生成评语或发送报告。
  • 报告内修改的学习内容及更新后的掌握情况只保存到本次正式报告，不更改教研管理-课件管理中的原课件学习内容。内容没有变化的掌握情况条目保留已有星值；新增或修改后的条目需重新评分。
4.课堂状况
  • 课堂状况包含总体表现、学习态度、课堂互动、听讲情况，每项使用 1-5 星评价，四项均必填；默认读取上一课次该生对应星值作为当前可编辑评分初始值。若某维度有上一课次星值，则在星级控件右侧显示「上一课次 X星」参考标签，并在标题旁展示「上一课次评分仅供参考」；若某维度无上一课次星值，则不显示该维度参考标签，星级保持空星。
  • 课堂状况标题右侧显示文案「较上一课次」。每个维度在本次星值同行显示相对上一课次的变化：本次高于上一课次时显示绿色「↑ 上升X星」，相同时显示灰色「— 持平」，低于上一课次时显示红色「↓ 下降X星」。某维度没有上一课次星值时，该维度不显示变化标签；四个维度均无上一课次星值时，不显示「较上一课次」文案及整列变化。
5.掌握情况
  • 掌握情况不再按听、说、读、写维度展示，改为按本节「学习内容」逐行展示，每行后保留 1-5 星评价；该区域为必填，所有学习内容行均需完成星级评价；不展示学习内容前置标签，也不展示星值后的 5 个关键词、关键词复选、关键词搜索输入框或下拉标签树。
  • 掌握情况示例学习内容：1.生字詞：露、芽、早晨、散步、香、請、成等；2.學會草字頭，並能舉出草字頭的字、詞語；3.學會句型「時間+人或物+地點+事件」；4.學會用感官去感受世界。
  • “上一课次”按实际上课时间定义：在同一学生、同一课程下，筛选实际上课时间早于当前课次且已有正式报告数据的上课记录，取实际上课时间最接近当前课次的一条，作为该生在本课程最近一次上课情况；不按课次编号或课次名称判断。无符合条件的记录时，视为无上一课次。
6. 生成评语
  • 前置条件：
  • 评语右上角提供「生成评语」按钮，点击后展开三种生成类型：温和鼓励型、建设指导型、行为习惯型；选择类型前校验课堂状况四个维度已完成 1-5 星评价、掌握情况所有学习内容行均已完成 1-5 星评价；满足条件后按钮进入禁用的「生成中...」状态，并结合课堂表现五星评价、掌握情况五星评价自动生成对应类型评语；若存在上一课次课堂星值，则作为可选输入一并传入提示词，用于辅助判断课堂状态延续性或变化趋势，若不存在则不传且不影响生成。短暂等待后将评语写入文本框，正文不展示类型选择前缀、星值或后台判断信息，并提示「已生成『类型』评语 X/3，可直接编辑后发送。」；单个课次单个学生最多生成 3 次。港澳地区的生成繁体中文，非港澳地区的生成简体中文。生成提示词以 生成正式报告评语提示词V2-学习内容五星.md 为准。https://study-report-rosy.vercel.app/生成正式报告评语提示词V2-学习内容五星.html
  • 生成评语演示例子基于示例输入：校区为香港/HK；课堂状况为总体表现 4、学习态度 5、课堂互动 4、听讲情况 4；上一课次课堂状况作为可选输入为总体表现 4、学习态度 5、课堂互动 4、听讲情况 4；掌握情况为生字詞 4、草字頭 2、句型 4、感官表達 3。原型 dev 导航提供三类评语示例入口，进入后预置上述星级与对应评语。
6. 发送报告效验

  • 1V1正式报告与班课正式报告维度相同，不同点班课发送学生是多个。

用户故事：

作为老师，我希望确认下课后立即填写本课次正式报告，无需退出课堂后再进入学习报告列表查找对应学生和课次。

前置条件：

  • 老师已进入正在上课的课堂，且当前课堂已关联学生、课程和课次。
  • 当前课次属于需要生成正式报告的课次，老师具备正式报告填写权限。

触发与交互流程：

  1. 老师点击课堂右上角「下课」，并默认在当前页面上方弹出「正式报告填写」弹窗；老师无需再次进入学习报告列表。
  2. 正式报告填写弹窗复用 7.2.1「填写正式报告」的字段、必填校验、评语生成及发送规则。

数据带入规则：

  • 发放学生默认带入当前课堂关联的学生；课程名称和课次默认选中本次实际结束的课程及课次。若无学生出勤，无需弹出报告填写弹窗。
  • 学习内容根据当前课程、课次对应的课件内容自动带出；课堂状况、上一课次星值、掌握情况等数据按 7.2.1 的既有规则初始化。
  • 自动带入的课程、课次必须以本次下课记录为准，不因课次编号顺序或老师曾打开其他报告而改变。
  • 系统按学生、课程、课次和报告类型校验正式报告记录。同一学生同一课次已有待发送报告时，直接打开原待发送报告，不得重复创建（把原有填写报告记录取过来）。
  • 同一学生同一课次的正式报告已发送时，不再打开可编辑填写弹窗，提示「该课次正式报告已发送」。

关闭与发送规则：

  • 老师在弹窗中点击「发送报告」时，系统执行 7.2.1 的完整必填校验；发送成功后关闭弹窗，报告进入「已发送」。
  • 报告未满足必填条件时保留弹窗及已填写内容，并在对应字段显示校验提示，不影响已经完成的下课状态。

验收标准：

  • 点击「确定」且下课成功后，正式报告填写弹窗自动出现，并正确带入当前学生、课程、课次和学习内容。
  • 对同一课堂（课次）重复点击[下课]触发流程时，不新增重复正式报告。

8 非功能要求

8.1 消息通知

8.1.1 学习报告发送通知

触发条件：

  • 老师或学管点击「发送报告」且发送成功。

通知类型：

  • App 推送、App 内消息。短信、邮箱是否发送待确认。

通知模板：

  • 您有一份新的学习报告，请进入「学习报告」查看。

参数：

  1. 学生姓名
  2. 报告类型
  3. 课程/报告标题

通知例子：

  • 梓霖，您有一份新的正式学习报告，请进入「学习报告」查看。

8.2 性能要求

  • 后台学习报告列表查询在常规筛选条件下接口响应不超过 2 秒。
  • 学生 App 学习报告列表首屏渲染不超过 3 秒。
  • 报告详情图表、标签和图片资源懒加载，避免长报告阻塞首屏。
  • 学生姓名/ID筛选需走索引或搜索优化，不得因模糊查询导致全表扫描超时。

8.3 安全要求

  • 数据权限隔离：老师仅可查看和填写自己授课或被授权班级/学生的报告；学管按校区和班级权限查看。
  • 学生端权限隔离：学生和家长只能查看本人或绑定学生的已发送报告，禁止通过报告 ID 越权访问。
  • 数据脱敏：后台列表可展示学生姓名；涉及手机号、身份证号等敏感信息时必须掩码展示，本次页面不新增敏感字段展示。
  • 操作审计：发送报告、查看详情、附件上传、报告状态变更需记录操作人、操作时间和报告 ID。
  • 附件安全：图片、文档上传需校验文件类型、大小和安全扫描结果。

8.4 兼容性要求

  • 历史接口字段如仍使用 class_type 表示原「班级类型」，前端文案必须展示为「报告类型」，后端可通过字段映射兼容。
  • 历史报告类型正式、试听课、转老师试听、阶段不变；新增总结报告不得影响历史数据查询。
  • 学生 App 已发送历史报告继续可查看；未补齐新字段的历史正式报告按已有字段展示。
  • 报告类型为空的历史数据需按原系统规则归类；无法归类的数据后台展示为「未知类型」，不在学生端新增展示。
