一、需求背景

排行榜需求概述（2026-10-14）

学校管理员在后台控制排行榜对学生展示；学生在 App 查看任务与练习表现，按时间及班级、年级切换榜单，查看前10名及自己的分数。

涉及端口 · 菜单 · 功能点

  1. 学校 Web｜学生管理 → 排行榜：任务与练习榜单使用「對學生展示排行榜」开关。
  2. 学生 App｜排行榜：白底排名列表、前10名、榜内外本人行及筛选；底部导航按學習、任務、排行榜、課程排列。

学校 Web 现有学生、班级与任务数据已经支持日常教学管理，但缺少按学年学期沉淀的排名结果展示与学生端激励反馈。学校管理员和班主任需要按学期查看班级排名并控制学生端可见；学生和家长则需要在 App 相关学习场景中查看自己的排名表现，形成学习激励闭环。

二、需求目标

  1. 建立学校维度的学年学期管理能力，其中班级按学年归属，排名按学年学期统计。
  2. 在学校 Web 为管理员/班主任提供学生排名榜单查询、导出和学生端可见控制。
  3. 在学生 App 提供底部排行榜入口，支持任务与练习总分、班级与年级、本周与本月及本学期切换，展示榜单及本人表现。
  4. 支持学生在学状态维护，避免轉移/離校/畢業学生继续进入当前任务和排名流程。
  5. 原型界面默认以繁体中文显示，学校名称示例使用「鳳溪第一小學」，便于贴近香港学校场景评审。

七、需求功能详述

7.1 学校Web——设定——学年学期管理

学年学期管理位于学校 Web「設定 / 學年學期」，用于统一维护学校学年、学期时间口径。学年、学期状态均由系统按当前日期自动判断，不提供人工启停入口。

7.1.1 新增/编辑学年

对应页面：

  • 前端：index.html - 学校 Web / 設定 / 學年學期 / 新增學年、編輯學年

用户故事：

作为一个学校管理员，我想要维护学校学年，以便班级、任务、练习和排行榜都按统一学年口径统计。

前置条件：

  • 用户已登录学校 Web。
  • 用户具有「設定 / 學年學期」菜单权限。
  • 用户具有新增或编辑学年的操作权限。

核心逻辑：

  • 通过「新增學年」或学年列表「編輯」进入同一弹窗。新增场景生成新学年记录，编辑场景回显原数据并在保存后覆盖更新。
  • 日期字段由日期选择器回填，避免用户手输导致格式不统一。保存时仍以后端校验结果为准，前端提示只作为即时反馈。
  • 学年状态由系统根据当前日期和起止日期自动计算，新增/编辑弹窗不提供手动维护入口。状态结果只用于列表展示和默认学年判断。
  • 保存时需同时校验学年唯一性、起止日期先后关系，以及与已有学期日期的覆盖关系。若该学年下已有学期，学年范围不得缩小到无法覆盖既有学期。
  • 保存成功后，学年作为班级、学生、任务、练习和排行榜的统一时间口径。默认取数逻辑优先使用当前「進行中」学年。

  • 榜单支持范围、指标和时间切换；切换后排名列表、名次升跌和本人行同步刷新。默认展示逻辑以字段说明为准。
  • 公开榜单按名次顺序展示，当前用户在客观榜单中展示学生姓名或脱敏名称，不展示「我自己」。本人上榜时在列表对应行以浅蓝色突出；榜外时在筛选下方展示浅蓝「我」行，仅显示头像、姓名和分数。
  • 本人上榜时显示实际名次、升跌及距上一名差值；榜外本人行不显示名次、升跌或追赶文案。

8 非功能要求

8.1 消息通知

  • 本次需求不新增消息通知。

8.2 性能要求

  • 学校 Web 列表首屏渲染不超过 3 秒。
  • 学生 App 排行榜首屏渲染不超过 3 秒。
  • 排行榜接口支持分页或 Top N 查询，避免一次性返回全量大班级数据。
  • 升級數據導入每次总行数不超过 5000 条，文件解析、预览校验和确认导入需分步执行，避免长事务阻塞。
  • 并发能力满足 500 QPS 稳定运行。

8.3 安全要求

  • 数据权限：学校管理员仅可查看本校数据；班主任仅可查看授权班级数据；学生仅可查看本人及被公开的榜单信息。
  • 数据脱敏：学生端榜单如展示同学姓名，应按业务规则进行适度脱敏或仅展示昵称。
  • RBAC：严禁通过修改 URL 参数查看其他学校、班级或学生数据。
  • 操作审计：学年/学期新增编辑与日期变更、账号新增/更新、升級數據導入每步确认导入、班级新增/编辑、学生新增/编辑、学生状态变更、可见开关变更需记录操作日志。

8.4 兼容性要求

  • 历史数据处理：在26年8月14日升级之前，将当前所有正式学校的【班级】都归入2025-2026學年，学年起止日期： 2025-09-01 ~ 2026-08-31； 上学期起止日期 2025-09-01 ~ 2025-01-30；下学期起止日期：2026-02-02 ~ 2026-08-31。
  • 历史学生记录保留原学生编号、班级学号和学校关系。
  • 原学生 App「任务」页既有未完成/已完成/已过期切换与任务卡列表保持不变，右上角保留原学习报告图标；排行榜通过底部导航进入；「我的」页既有信息卡、操作指引、账号信息与退出登录能力保持不变。
  • 学校 Web 原有班级管理、学生列表筛选和编辑能力保持可用。
  • 学校 Web 和学生 App 原型默认显示繁体中文；若后续进入开发，需复用现有系统的繁简体语言切换能力。
  • 学校名称作为学校配置项展示，原型示例为「鳳溪第一小學」，不得写死为固定业务数据。
